## 一、项目概览

将「亮宅」整套系统 1:1 克隆到本地：

| 端 | 形态 | 说明 |
| --- | --- | --- |
| 前台（亮宅操作端） | Web 化 Electron SPA | 原桌面客户端编译产物（`vendor/liangzhai`）原样复用，界面/按钮/弹窗与线上完全一致 |
| 后台（装企后台） | SPA 原样托管 | `vendor/enterprise`（enterprise.e-shigong.com），14 个导航页 + history 路由直访/刷新 |
| 后端 | 零依赖 Node 服务器 | 静态托管 + API 代理 + 响应录制/离线回放 + 本地 API 层（625 handlers） |

**核心承诺**：前端 SPA 布局样式零改动（一个字节不动）；后端逐接口与原站双跑对比，结构一致才放行本地化；每块完成页面级测试后再进下一块。

## 二、架构设计

```
浏览器 ──> http://localhost:8010
              │
              ├── 静态托管（/liangzhai/ 前台、/enterprise/ 后台、/img 等本地资源）
              │
              └── /api/* 请求分发（LOCAL_MODE=on 默认）
                    │
                    ├── 1) isLocalBlocked？ 黑名单接口 → 直接代理（未验收/动态数据）
                    │        └── 白名单优先放行（已验收接口）
                    │
                    ├── 2) 本地 handler 命中？（625 个，local-api.js）
                    │        ├── 读接口：SQLite/快照/mock 本地服务（离线可用）
                    │        ├── 写接口：宽容落库（防云端污染）+ 后台双跑对比（读接口）
                    │        └── 未命中 → 代理
                    │
                    └── 3) 代理层（proxyToApi → lzapi.e-shigong.com）
                           ├── 混合认证：本地会话 ↔ 云端凭证映射（session-id/user-id/company-id/platform）
                           ├── 响应录制：JSON 全部录制；导出类二进制 base64 录制（含下载头）
                           └── 离线回放：LZ_FIXTURE_MODE=offline 时纯本地（fixtures 649 个）
```

### 关键机制

| 机制 | 说明 |
| --- | --- |
| **LOCAL_MODE** | `on`（默认，本地优先）/ `observe`（影子运行+双跑 DIFF）/ `off`（纯代理） |
| **LZ_FIXTURE_MODE** | `auto`（真实优先+录制+回放）/ `live`（仅真实）/ `offline`（仅回放） |
| **LOCAL_BLOCK 黑名单** | 结构失真/未验收接口走代理（前台 user/project/crm/im/finance/oa 等前缀） |
| **LOCAL_WHITE 白名单** | 已验收放行的路径（在黑名单之上优先），逐接口验收后加入 |
| **写接口保护** | 本地命中的写接口（增删改/状态/排序/转移）**跳过 DIFF 后台对比**，防真实写云端 |
| **混合认证** | 本地登录自动同步云端 company 会话，代理时映射凭证；会话过期自动失效（需重新登录） |
| **二进制录制** | 导出 excel 等非 JSON 响应按 base64 存储 + content-disposition，离线还原字节流 |
